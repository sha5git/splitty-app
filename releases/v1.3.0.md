## Release notes

Feature release for **Splitty** that refreshes group data as soon as someone else changes it, and lets you install the app to the home screen.

### Features

**Live updates**
- Group members see new or edited expenses, settlements, members, and balances within about a second while both have Splitty open
- Replaces the 30-second poll with `GET /api/events/stream` (SSE); REST remains the source of truth
- Falls back to a slow poll only if the live stream is disconnected

**Installable app (PWA)**
- Add Splitty to the home screen (Chrome / Android) with standalone display
- Web app manifest, teal theme, and PNG icons
- Service worker precaches static assets only — API and live stream stay on the network

**API**
- `GET /api/events/stream` — Server-Sent Events of `group-change` messages (Firebase Bearer token)

### Infrastructure / quality

- OpenAPI updated; frontend types regenerated
- Service worker uses `injectManifest` so push notifications (Phase 4) can extend the same worker
- Nginx: if the live stream stalls after deploy, disable proxy buffering for `/api/events/stream`

### Known limitations (unchanged)

- Equal splits only (no custom or percentage splits yet)
- Email-based member lookup only
- Single-server Termux hosting (personal/demo scale)
- No OS push notifications yet when the app is closed (planned Phase 4)
- Install / service worker require HTTPS (production). Local `npm run dev` does not register a service worker
